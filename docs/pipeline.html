S2 · Feature engineeringper sample
Waveform 16 kHz mono (resample if needed) → 3.0 s window, right-aligned to speech end (VAD) — window ends at t1 + 0.5 s (t1 = last voiced frame, frozen audit CSV), front-pad silence (VAD audit: 0.6 / 1.7 / 17.9% of train / test / holdout carry ≥ 3.0 s trailing silence)
train only: MUSAN mix in waveform domain, SNR 5–25 dB → STFT Hann 1024 (64 ms) · hop 320 (20 ms) → 513 bins → 80-mel filterbank (50–8000 Hz) → power → log10 (clip 1e-5) → (x+5)/5 → [0,1] → 151 → 150 frames (drop last, right-aligned)
train only, order matters: time-warp 0.95–1.05 (mel, tail preserved) → gain ±10 dB (mel) → (1, 80, 150) float32

S3 · Train one epochper epoch
Model: bcresnet scale=2 — 30,134 params @20c (fallback v2cnn 98,022, same input) → shared feature tail forks into 1 command head Linear(20) + 6 slot heads Linear(3) (slot heads read the last ~1.3 s tail — where the slot value is spoken)
Loss: L = L_cmd + 1.0 · L_slot — L_cmd: class-weighted CE over all clips (frozen w); L_slot: unweighted CE over valid slotted clips only (batch mean; 0 if none) — NaN-slot clips contribute command-only loss
Optimizer: AdamW lr 1e-3 · wd 1e-4 · cosine schedule · batch 32 · patience-based early stop (V2-validated settings, carried over)
Logged per epoch: L_cmd, L_slot, all test metrics (S5)
↓ epoch end → evaluate on TEST
S4 · Model selection (lexicographic, FROZEN)per epoch · TEST

B End-to-end system RPi 4B · ONNX Runtime CPU · no ASR / LLM / cloud

Always-on two-gate design: the wake gate (V2, reused) decides when to listen; the VCM (V3, 20-class + slots) decides what to do. Both consume the same numpy-mel computed once per window. Defense in depth vs V2's silent-fire bug: gate 1 (wake) + gate 2 (OOS class).

B1 · Capturealways on
mic (USB / 3.5 mm) → ALSA, 16 kHz mono int16 — assert locked 16 kHz (V2 flag: naive np.interp resample is only safe with a locked rate)
→ tmpfs ring buffer (rolling 3.0 s = 48,000 samples) — tmpfs on purpose: SD-card I/O is the bottleneck (V2 lesson)
↓ each rolling 3.0 s window
B2 · Feature (numpy, on-Pi)per window
speech-end anchor (live mic: capture timeout; file replay: VAD t1) / left-pad → STFT (Hann 1024, hop 320) → 80-mel (50–8000) → power → log10 → (x+5)/5 → (1, 80, 150) float32
window + filterbank loaded from shipped buffers (mel_window.npy 1024, mel_fb.npy 513×80) — bit-exact with HPC training features (verified by verify_pi_v3 before demo)
↓
B3 · GATE 1 — wake model (V2 bcresnet, reused — no retrain) (1, 80, 150) → (1, 2)
2-class "hey boots" — V2 numbers: balanced 0.9990 · wake recall 0.94 · no-wake false-positive 0.0000; ONNX parity already verified
no_wake → keep listening (loop below) · wake → start command capture
↩ no_wake loop: advance window, re-run wake gate — this is the always-on front-end. V3's new command phrases are automatically no_wake; no wake retraining needed.
↓ on wake
B4 · Command capture windowper command
record until 600 ms RMS silence timeout or 3.0 s cap → right-pad to exactly 3.0 s → same numpy-mel → (1, 80, 150)
↓
B5 · GATE 2 — VCM model (V3 bcresnet scale=2 · 30,134 params) (1, 80, 150) → cmd (20) + 6 × slot (3)
shared BC-ResNet feature tail → command head (20 classes: 19 intents + OUT_OF_SCOPE, global pool) + 6 slot heads (3 whitelisted values each, read the last ~1.3 s tail where the value is spoken)
≤ 100 ms per 3 s clip on RPi 4B ONNX CPU (stretch 50 ms) — pre-registered target
↓ softmaxes
B6 · Decision gatesper command

reject — no action

argmax = OUT_OF_SCOPE — wake gate let a non-command through; the OOS class (weight 5.214) refuses to fire (second rejection layer)
confidence < pre-registered threshold — threshold frozen from the OOS softmax curve on TEST before run 1 (V2 set it ad hoc — fixed)

accept — dispatch

command = argmax of 19 intents; slot (slotted intents only) = argmax of that intent's 3-value head → canonical slot value
e.g. "set the alarm to 8 AM" → ALARM + 8 AM (locked vocab: 6 AM / 8 AM / 9 PM)
↓ on accept
B7 · Actuation — intent dispatch19 intents
slotted (6): ALARM 6 AM · 8 AM · 9 PM → alarm app · TIMER 10 seconds · 30 seconds · 1 minute → countdown · TEMPERATURE 18 · 22 · 26 degrees → HVAC · BRIGHTNESS 20 · 60 · 100 percent → lights · COLOR red · blue · green → lights · CREATE_REMINDER drink water · study · exercise → reminders
fixed (13): PLAY_MUSIC / PAUSE / NEXT / STOP → media player · VOLUME_UP / VOLUME_DOWN → media volume · LIGHT_ON / LIGHT_OFF → lighting · WEATHER / TIME → info display · CALL / MESSAGE → dialer / messaging app · LIST_REMINDERS → reminders list UI
dispatch = local app/CLI/GPIO calls on the Pi — no cloud round-trip
↓
B8 · Feedback UI + loggingper command
ack = beep + LED only — NO spoken confirmation (echo protection: a spoken ack re-triggers the mic, V2 lesson)
LED states: off = sleeping · pulse = wake, listening · green = accepted + action · amber = rejected (OOS / low confidence)
per-trial log line (group benchmark protocol): evaluator_id, trial, command, audio_file, predicted_class, correct, latency_ms

On-device budget (hard spec)

models: wake_model.onnx + model.onnx ≈ < 1 MB total (VCM ~120 KB)
runtime: ONNX Runtime CPU only; mel = numpy (no FFT op in any graph); ~2 GB RAM headroom (waveform cache is HPC-side only)
latency: wake gate per rolling window (30K-param model) + VCM per command ≤ 100 ms — end-to-end "last word → action" ≈ < 1.5 s (600 ms timeout dominates)

Invariants (why it works)

one feature, two models — the exact same (1,80,150) numpy-mel feeds gate 1 and gate 2; bit-exact parity (S6 / verify_pi_v3) is the deploy gate
two independent rejection layers — wake gate (front) + OOS class (back) kill V2's silent-fire bug from both sides
slot = last word — right-aligned window guarantees the value sits in the tail the slot heads read
